# T6 · dsh-shorekeeper-wechat —— 微信接入

```
状态: todo · owner: · 预估: 12–16 agent 小时 · 前置: T1
分支: T6-wechat
```

## 目标

守岸人知道微信里发生了什么：新消息摘要进上下文、按需代读、经确认代发。**默认只读不发**。

## 背景

生态无现成个人微信接入件。接入路线需真机选型验证（能力覆盖 × 风控风险 × 维护成本）。

## 步骤

### 阶段一：路线选型（3–5h）
- [ ] 候选调研：企业微信/公众号合规 API · wechaty（各 puppet）· wechatferry/wcferry（Windows 挂机）
- [ ] 各写 200 行内 PoC：收一条消息、发一条消息到文件传输助手
- [ ] 决策记录：覆盖面、封号风险、部署形态（挂哪台机器）、维护成本
- [ ] 若选 Windows 挂机：复用 win.lan 探针机器，出部署文档

### 阶段二：插件实现（5–7h）
- [ ] 消息桥：接入层收消息 → 归一化事件（会话/发送人/类型/摘要）
- [ ] `wechat.digest`：未读摘要按会话分组，人名脱敏可配
- [ ] `wechat.read`：指定会话最近 N 条（验证码/转账类只提示不代读全文）
- [ ] `wechat.send`：审批 + 联系人白名单 + 内容预览确认，白名单外硬拒
- [ ] 事件注入：新消息摘要进上下文/推 k20 字幕，频率保守（默认仅白名单联系人）

### 阶段三：安全与打磨（4h）
- [ ] 红线清单逐条落实（见下）+ 渗透自测（伪造发送人、超权发送）
- [ ] 通知兜底：叠 dsh-mobile-notify
- [ ] 单测（mock 微信桥）+ 真机验收记录

## 交付物
- `plugins/dsh-shorekeeper-wechat/` 完整实现
- 路线决策记录 + 接入层部署文档
- 安全红线清单与自测记录

## 验收标准
- [ ] 真实收一条微信消息 30 秒内摘要可见
- [ ] 代发走审批；白名单外联系人被硬拒
- [ ] 验证码/转账类消息不被代读全文
- [ ] 接入层崩掉时插件优雅降级，不影响 dsh 其他能力

## 拓展方向 / 未来方向
- 拓展：群消息 @我 优先级排序；重要联系人专属提示语
- 未来：快递/日程类消息自动归入生活流；守岸人代拟回复草稿

## 风险与对策
| 风险 | 对策 |
|---|---|
| 个人微信自动化封号 | 只读为主；发送极克制；决策记录里量化风险并由漂泊者签字 |
| 接入层不稳定 | 桥与插件解耦，桥崩可重启不丢状态 |
| 隐私 | 脱敏默认开；消息只存摘要，全文即时取即用不落盘 |
