## 安卓桌面 App 卡在「连不上 Hub」——根因与修复（22:20–22:35）

- 现象：k20 桌面屏左下角常驻 `连不上 Hub：unexpected end of stream on http://10.14.14.117:3090/...`（uiautomator dump 才拿到完整文案，界面上是单行省略号）。网络与 Hub 全好：设备上 `toybox nc` 直发原始 HTTP 拿 200 + 完整 JSON；重启 App 立刻恢复。CPU/MEM/GPU 一直在变——那是 mini 面（独立轮询），hub 快照那一路才是死的。
- 排查要点（可复用）：
  - adb 在 Windows 上（`ssh weiek@10.14.14.170`，设备 da8a8958，Redmi K20 Pro）。远程命令的引号/管道会被 cmd 吃掉——**任何脚本走 `ssh ... "adb shell sh" < local.sh` 用 stdin 喂**，最稳；设备上没有 /tmp，写文件要 `/data/local/tmp`。
  - `uiautomator dump /data/local/tmp/x.xml` + 本地正则取 text 是读桌面屏文案的最快办法（Compose 也暴露 semantics）。
  - App 配置在 `su -c 'cat /data/data/cn.weiekko.dock/files/datastore/dock_hub.preferences_pb'`：host=10.14.14.117、port=**3090**（protobuf int，strings 看不到，要 xxd 解）、token 与 hub.yaml 同一串。
  - `toybox nc` 有个坑：stdin EOF 就关连接，长轮询/空闲复用类测试它会秒退（bytes=0），别当成服务端问题。
- 根因两层：
  1. Hub 响应头 `Keep-Alive: timeout=5`（Node 默认），OkHttp 空闲连接留 5 分钟 → 两次请求隔 >5 秒必然撞上死连接报 `unexpected end of stream`；而客户端 `retryOnConnectionFailure(false)`，这种必然自愈的失败直接冒到主屏。
  2. `restartPolling` 的 while 循环没有兜底：一轮抛意外异常 coroutine 就静默死（不崩、无日志），横幅永久挂着——桌面屏 7×24 没人手点重启。
- 修复（dock 仓库 main 已合并，提交 2ef7a78，分支 fix/k20-hub-poll-selfheal，**未 push**）：
  - `HubClient`：幂等 GET 失败换连接重试一次（`retrying()`），POST 不重试（点灯/场景副作用不能翻倍）。
  - `DockViewModel`：每轮 try/catch（CancellationException 上抛）+ 看门狗 `startPollWatchdog()`（60 秒没成功快照就重建轮询）+ `handleFailure` 补 `Log.w("DockVM", …)`。
  - 实测：断网 80 秒 → logcat `poll stalled 67693ms, restarting polling` → 恢复后横幅自动消失、CPU 数值继续走。
- 构建/装机（Mac 无 JDK，用 Android Studio 自带）：`JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew :app:assembleDebug --offline`（+ `:app:testDebugUnitTest`），APK 272MB；`scp` 到 Windows `C:\Users\weiek\AppData\Local\Temp\` 再 `adb install -r -d`。已装的是 debuggable 包（debug keystore），所以 `-r` 覆盖升级不掉配置（host/token 都在）。
- 遗留观察：hub 快照里 `pc.updated_at` 冻在 2026-11-14T23:43（desk 心跳 `/v1/desk` 没再来），但 `pc.cpu.percent` 仍在变——桌面上的 CPU/MEM/GPU 走的是 mini 面（Windows，RTX 4060），所以显示是新鲜的；pc 时间戳这条链待查（不影响当前观感）。

## 22:40–23:10 · k20 侧栏「主屏布局」补回背景壁纸（上传/切换/删除/恢复纯色）

- 起手排查：plugins/dsh-shorekeeper-k20/client.js 在 main 里只有槽位拖拽（Clock/Pc/Win*/Device*/Media/Weather/Indoor 十个槽），`grep 壁纸` 全仓零命中、`git log -S"上传壁纸"` 也没有——面板**从来没做过**壁纸 UI。壁纸能力一直只存在于 agent 工具 `k20_wallpaper` 和手机自带网页（`:17920` 的「岸亭背景」页）。所以不是「掉了」，是「没接」。
- 这次把它接进面板，分三处：
  - `src/background-client.ts`：新增 `mediaResponse(id)`（代持 cookie 取原文件流，401 重登一次）与 `uploadStream(filename, iter, realName, payloadLength)`（Readable.from + fetch duplex:'half' 边收边转）。
  - `src/index.ts`：`/k20-layout` RPC 新增 `backgrounds/select/remove/clear` 四个 action；另挂 `/k20-bg` 前缀路由——`GET /k20-bg/media/<id>` 转发手机原文件（带 content-type/length），`POST /k20-bg/upload?name=&realname=` 把请求体流式转成 multipart 给手机。
  - `client.js`：面板下半部「背景壁纸」区块——署名输入（默认守岸人）、上传壁纸（隐藏 file input，accept jpg/png/webp/mp4）、刷新、恢复纯色；卡片网格带缩略图、大小、署名、使用中标记、切换/删除；视频不预加载（点缩略图新窗口看），避免几十 MB 的 moov 一开面板就拉。
- 踩坑（重要）：手机 `BackgroundServer.readForm` 用 `Content-Length` 构造 `LimitedStream`，**chunked 上传 length=0 → 当成没文件 → 400**。第一次测就撞上（`POST /api/backgrounds：HTTP 400`）。修法：转发时把 multipart 头/尾字节数算进去，显式带 `Content-Length = head + file + tail`；拿不到长度才退回 `collect()` 全缓冲 + 老的 `upload()`。
- 实测（都走 :3090，用 App 自己的 cookie）：`backgrounds` 返回 current=1.mp4 共十几项；`/k20-bg/media/sk_diaries_c.jpg` 200 / image/jpeg / 188959B（与手机一致）；上传 93KB 测试 PNG → `current=panel-test.png` 立即生效 → `select 1.mp4` 切回 → `remove panel-test.png` 删掉，状态复原，没留垃圾。
- 其他：`tsc --noEmit` 0 错、`vitest run` 56 passed / 13 skipped；重启走 launchctl bootout+bootstrap（token 会换）；bundle 里已能 grep 到「背景壁纸」「k20-bg/upload」，说明前端新码已进 `plugins/??…client.js`。
- 遗留：`/k20-bg/media` 不支持 Range（手机那边也不支持），视频在新窗口是整段下载后播，不能拖进度；面板视频缩略图目前只是 ▶ 占位，没做首帧截图。
