## 忙碌策略改成「打断」（11:30）
- 漂泊者：「会话改成打断方式 不要顺序发送」。原来 `busyMessageMode` 走默认 `queue`——回复没写完时新消息排队，等上一条答完才答。
- 新增第三个取值 `interrupt`（上游只有 queue/steer）：`agent-bridge.js` 加 `#preempt()`——消息入队后立刻 `agent.cancel({kind:'user'})` 砍当前轮，旧轮 `#awaitReply` 见 `record.cancelled` 早退（返回 `{cancelled:true}`，index.js 静默不发气泡），finally 里 drain 队列 → 新消息 100ms 级开跑。队列仍 FIFO，不丢已排队的消息。
- 改动三处（均在 dsh-plugin-weixin patch 内）：`agent-bridge.js`（mode 解析 + #preempt）、`index.js`（z schema union 加 interrupt）、`config-remote.js`（设置面板选项「打断当前回复，立刻处理新消息」）。patch 18763B → 25629B，文件数 3 → 4。
- 配置：`~/.dsh/profiles/web/cordis.patch.yml` 的 weixin 段加 `busyMessageMode: interrupt`；回滚=改回 queue + 重启。`/steer <指令>` 仍是注入（打断模式下优先判 steerCommand）。
- 验证：harness（/tmp/wx-interrupt-test.mjs，mock agent + 假 @deepseek-ai/dsh-llm）9 条断言全绿——打断模式下第二条 131ms 答出、旧轮 cancelled、cancel 调用 1 次；对照 queue 模式第二条等 2994ms。生产实例已重启（health ok，插件 instance.lock/metrics 11:29 刷新），YAML 解析确认 busyMessageMode="interrupt"。
