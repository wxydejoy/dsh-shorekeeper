## 语音"卡卡的" = Qwen3-TTS 生成失控（已修）

**现象**：用户报语音卡顿。dsh 00:38 重启，tts.log 尾部大量 `POST /v1/audio/speech 502`。

**排查要点（下次省时间）**：
- `/v1/audio/speech` 的 502 **大多数是正常的 barge-in 打断**，不是故障。`/v1/stop` 触发 `InterruptedError`，在 `/v1/speak` 分支落到通用 `except Exception` → 502 `tts_error`。tts.log 里 `/v1/stop` 1077 次 vs 502 53 次，基本一一对应。别被 502 数量唬住。
- 真正的判据是 `tts latency ... ms= bytes= chars=` 三者的比例。正常约 **201ms/字、0.25 秒音频/字**（24000Hz 16bit → 48000 bytes/s）。
- 真凶：**3 次失控**，27 字吐出 328 秒音频（15.7MB）、36 字吐 328 秒、27 字吐 240 秒，单次耗时 142s / 167s / 98s。三次都在最后 2000 行内（行 528101 / 529077 / 529924），即最近集中出现。

**根因**：`mlx_audio` 的 `Qwen3TTS.generate()` 默认 `max_tokens=4096`，模型 12Hz → 4096 token ≈ **327 秒音频**。模型一旦卡进重复循环就一路吐满上限，听感是拖长/鬼打墙/卡住。

**修法**（`~/dock/companion/tts/server.py`，备份 `server.py.bak-20261118-004253`）：
1. `speak()` 里按字数给长度预算：`max_tokens = max(256, min(4096, len(text)*12 + 64))`（≈4 倍余量）
2. 双保险时长守卫：`max_audio_sec = max(12.0, len(text)*0.9)`，累计音频超限就 `break` 并打 `tts guard 截断` 日志
3. 补诊断：`/v1/speak` 的 `except Exception` 改成**先 print exc 再回 502**。原来客户端先断开，`_json(502)` 撞 BrokenPipe，二次 traceback 把真错误盖掉，线上只看到 502 无从查。

**验证**：5/17/39 字 → 1167ms/1870ms/3342ms，音频 1.9/4.4/8.2 秒，86–233ms/字，正常。

**排查过的伪线索（排除）**：
- `dsh-web.err.log` 里 `cannot get property "webServer" without inject`（dsh-keeper-console / dsh-shorekeeper-k20 / dsh-shorekeeper-reading）：共 19 次，最后一次在 585/694 行，**00:38 那次启动已无此错**，历史问题已修，与本次无关。
- k20 app（10.14.14.177）正常：`WakeWord: kws listening rms≈0.001 speaking=false`，无播放异常。
- TTS `/health` 一直报 `ready:true`，健康检查**查不出这种失控**——必须看 latency 日志的 bytes/chars 比例。

**认证备忘**：curl 探 `/v1/companion/*` 仍是 302→带 token URL→401，用 logs 里的 token 过不去，门卫 :3093 会 302 到 `?token=`。没深究，不影响实际链路（手机侧是配好的）。

## 新闻播报（dsh-keeper-news，新插件）

**形态**：早晚定时（默认 08:30 / 21:00，错过 90 分钟内补）+ 点播「播一下新闻」。综合热点，5 条约 32 秒。

**源**：只用百度热搜 `top.baidu.com/api/board?platform=wise&tab=realtime`（免 key，53 条，字段只有 word/url/index/isTop，**没有摘要和数值热度**）。实测排掉的：腾讯新闻直连 503/501 跳 WAF、微博热搜 403、第三方镜像连不上、`m.baidu.com/s?word=` 要人机验证。RSS 留 `extraFeeds`（新浪/36氪/少数派可达），默认空。

**设计取舍**：
- 定时播报**不过模型**（keeper-watch 同口径）：热搜只有标题，模型只能同义改写；模板稿零成本。
- 出声走 keeper-tts `play:true`，**逐段送**（36 字包/上限 52，规则抄 `dsh-shorekeeper-reading/src/speech.ts`，跨插件不 import，改口径两边一起改）；`/v1/stop` 只损失当前小段。
- 「今天这一档播过」落 `~/.dsh/keeper-news-state.json`（只存内存的话 21:00 播完重启一次就再播一遍）。
- 键鼠空闲 >10 分钟只推微信不出声（`ioreg HIDIdleTime`，取不到按「在」处理）。

**踩到的两个真问题**：
1. **工具 render 就是模型看到的全部**。`output.render` 只回 summary 时，`news_brief` 的 items/spoken 模型根本拿不到（冒烟时模型回「没有 items 字段」）。改法：render 里把条目+链接+榜位+口播稿全拼进文本。
2. **console 的 `setKeeper` 会吞掉别人的段**：原来只回写 `watch`/`deskMi`，而 `keeper-settings.json` 是几个插件共用——改一次提醒设置就把 `news` 段抹了。已改成三段整份回写，并加 `strIn` + 单测（空串 = 关掉那一档，不回落默认）。

**面板**：守岸人 → 设置 → 新闻播报（开关/早报/晚报/条数），写 `keeper-settings.json` 的 `news` 段，插件每分钟现读，不用重启。

**接口备忘**：`/api/dsh-console/cmd` 的参数在 **body.payload** 里，不是顶层（`{"op":"send","payload":{"sessionId":…,"text":…}}`）；`op:create` 不带 payload 也成功，别被误导。验证插件工具面就用这条路：create → selectModel(ark) → send → detail 看 `turns[].tools[].result`。
